# 阅痕 ReadTrace 纪念功能设计与开发计划

> 定位：把「读过的一本书 / 一个作品」变成值得纪念的存在。
> 本文基于 2026-08-22 对同类开源项目的调研，规划 v1.1 起的纪念功能数据模型与版本路线。

---

## 1. 调研背景与结论

### 1.1 调研对象

| 项目 | 形态 | 与阅痕的关系 |
|---|---|---|
| Openreads（Flutter，1.6k+ stars） | 隐私优先的书籍追踪 App | 功能最接近的正面对标 |
| BookDiaryMobile（Kotlin + Room） | 阅读日记 App | 技术栈相同的架构参考 |
| Every Read（安卓，闭源） | 私人阅读日记 | 产品设计理念参考（笔记绑定页码） |
| 「阅读记录」（iOS，闭源） | 打卡 + 时长 + 年度总结 | 国内赛道标杆，功能形态参考 |

参考项目已浅克隆到 `D:\zzd_project\cursor\hanshi sophomore2\参考开源项目\`（项目外目录，不进入本仓库）。

### 1.2 核心结论

1. **「纯记录」赛道已经成熟**：Openreads 把书单状态、标签、在线搜书、统计都做完了，阅痕 v1.0 的功能与之基本对齐，继续在这个维度追赶没有差异化。
2. **「纪念意义」是所有开源项目的空白**：没有任何一个项目做「那年今日」「周年回忆」「阅读里程碑」这类情感化功能。这是阅痕的差异化机会，也最贴合「让每本书有纪念意义」的初衷。
3. **数据模型是分水岭**：两个开源项目都是单表扁平建模（感想是书上的一个文本字段），无法沉淀过程性记忆。阅痕要做纪念功能，必须从 v1.1 开始引入独立的「摘录 / 笔记」子表。

## 2. 调研详情与借鉴点

### 2.1 Openreads（正面 + 反面教材都有）

**值得借鉴：**

- **多次阅读建模（最大亮点）**：一本书可以有多个 `Reading{startDate, finishDate, customReadingTime}`，支持「重读」场景；每条记录允许残缺（只记开始 / 只记完成 / 只手填时长），兼容真实记忆模糊的情况。旧平铺字段向 readings 结构迁移有现成 SQL 写法。
- **读完即评微交互**：状态切到「已读」时自动弹半星评分框（可跳过）并自动补完成日期，降低记录成本。
- **软删除 + 回收站**：`deleted` 标志位，查询默认过滤，有 trash 页可恢复——与阅痕现有软删除设计一致，可参考其恢复页交互。
- **封面文件分离**：数据库只存 `has_cover` + `blur_hash`，封面按 `{id}.jpg` 落盘，列表滚动不读大 BLOB，加载前显示模糊占位图。
- **统计维度设计**：所有指标统一按「全部年份 + 各年份」双维度输出，UI 用 Tab 切换；月度柱状图按载体格式堆叠分色。
- **年度阅读挑战**：按年设定读书数量目标，进度条展示。

**反面教材（阅痕要避免）：**

- 统计是全量书籍拉进内存用 Dart 循环算，每次进统计页重算，无 SQL 聚合、无索引。阅痕统计应下推到 SQL（如 `GROUP BY strftime('%Y-%m', finish_date)`）。
- 标签用 `|||||` 分隔的字符串 + LIKE 过滤。阅痕当前用 JSON 数组存储可接受，但若做标签筛选页，应考虑关联表或 SQLite JSON 函数。

### 2.2 BookDiaryMobile（主要是反面教材 + 工程参考）

**值得借鉴：**

- **封面图片管线**：相册 / 拍照（区分 Android 13 权限）→ uCrop 固定 2:3 裁剪 → 复制进内部存储 `files/covers/` → 库里只存路径；换图 / 删书时清理旧文件。阅痕未来做封面上传可照此方案。
- **响应式数据流**：`combine(排序, 搜索).flatMapLatest(查询).stateIn()` + `repeatOnLifecycle` 收集，搜索排序变化即时重查。属于未来重构方向，v1.0 不动。
- **ZIP 全量备份**：数据库 + 封面打包导出，导入含路径穿越防护。

**反面教材：**

- **单表无关系**：「日记」只是书行内的一段描述文本，没有日记条目表、没有页码 / 心情 / 多次感想。想做「阅读日记」必须重新建模——这正是阅痕 v1.1 要做对的事。

### 2.3 Every Read（产品设计参考）

- 笔记和摘录**绑定到具体页码**（如「第 192 页的私人批注」）——「位置即记忆」，翻回那页就能想起当时为什么划下这句话。阅痕 v1.1 的摘录表应有 `page` 字段。
- Slogan「Remember more from every book」与阅痕的纪念定位同源。

## 3. v1.1 摘录与笔记 —— 纪念核心层（数据模型设计）

### 3.1 设计原则

- 摘录 / 笔记是**独立实体**，与 books 一对多，不做书行内文本字段。
- 记录「内容 + 位置 + 时间」，位置（页码 / 章节）是纪念感的关键。
- 软删除策略与 books 完全一致，数据层不提供物理删除。
- books 表新增字段走 `onUpgrade` 迁移，数据库版本 1 → 2。

### 3.2 notes 表结构（草案）

```sql
CREATE TABLE notes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    book_id INTEGER NOT NULL,
    type TEXT NOT NULL DEFAULT 'excerpt',   -- excerpt=摘录 / note=随想
    content TEXT NOT NULL,                  -- 正文
    page INTEGER,                           -- 页码（可空，位置即记忆）
    chapter TEXT,                           -- 章节（可空）
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    is_deleted INTEGER NOT NULL DEFAULT 0,
    deleted_at TEXT,
    FOREIGN KEY(book_id) REFERENCES books(id)
);
CREATE INDEX index_notes_book_deleted ON notes(book_id, is_deleted);
CREATE INDEX index_notes_created ON notes(created_at);
```

说明：

- 先不做 `mood`（心情）字段，等 v1.2 观察需求再加，避免第一版表过宽。
- 时间戳格式与 books 一致（ISO_OFFSET_DATE_TIME 字符串）。

### 3.3 books 表迁移（版本 2）

- 无必须新增字段；`start_date` / `finish_date` 已存在，可支撑 v1.2 统计。
- 参考 Openreads：若未来要支持「重读」，再把起止日期拆成 readings 关联表（v1.x 内不急）。

### 3.4 v1.1 功能清单

1. Note 数据模型 + notes 表 + DAO（增、改、按书查、软归档）。
2. 书籍详情页新增「摘录与随想」区块：时间倒序卡片流。
3. 添加 / 编辑摘录页：内容必填，页码、章节可选。
4. 摘录卡片展示：正文 + 页码徽章（「P.192」）+ 相对时间。
5. 软归档书籍时，其 notes 一并隐藏（查询侧过滤，不做级联写）。

## 4. v1.2 统计与回忆 —— 纪念表达层（规划）

### 4.1 统计（SQL 聚合，避免 Openreads 的内存全量计算）

- 年度 / 累计：读书数、均分、最厚的一本、最快读完的一本。
- 月度读完柱状图：`GROUP BY strftime('%Y-%m', finish_date)`。
- 年度阅读挑战：目标数存 SharedPreferences（少量配置不建表）。

### 4.2 回忆（差异化核心）

- **那年今日**：启动时查询 `finish_date` 的月日与今天匹配的书籍，首页卡片位轮换展示「一年前的今天，你读完了《xxx》」。
- **里程碑**：第 N 本书达成时在首页庆祝一次（数据可由 COUNT 得出，无需新表）。
- **年度纪念页**：年末生成「我的阅读之年」静态页（数据全部来自现有字段聚合）。

### 4.3 封面（补完藏书感）

- 相册选图 → 裁剪 → 内部存储落盘，库里存路径（参考 BookDiaryMobile 管线）。
- `cover_url` 字段保留为「网络封面地址」，新增 `cover_path` 本地封面路径，UI 优先本地。

## 7. 3D 沉浸式方案（2026-08-22 新增）

### 7.1 设计意图

让摘录不止是「被存储」，而是「被翻开」——用 3D 交互把阅读记忆变成可以走进去的空间，强化沉浸式与纪念感。

### 7.2 三个场景与分级落地路径

| 场景 | 效果 | 落地版本 | 安卓实现方式 | 成本 |
|---|---|---|---|---|
| 悬浮封面卡 | 书籍卡片默认侧旋，触摸回正浮起 | v1.1 | XML `rotationY` + `translationZ`/`elevation`，一行属性 | 低 |
| 翻书摘录 | 摊开的书，左页摘录原文、右页页码章节随想，3D 翻页 | v1.1 | `ViewPager2` + `PageTransformer`（rotateY 页翻转），纸张质感用背景 Drawable | 中 |
| 3D 书架 | 书脊朝外的立体书架，视差环视、点击抽书 | v2.0 | Compose Canvas / SceneView(Filament) 做真实光影；v1.x 可先用 2.5D 封面墙过渡 | 高 |
| 书籍展览馆 | 每本书一座 3D 展厅，展品自定义添加、展厅随内容生长延展 | v2.0 | SceneView(Filament) 渲染房间，展品由 notes 等数据动态生成贴图平面 | 高 |

### 7.3 对 v1.1 功能清单的补充

在 3.4 节清单基础上新增：

6. 「翻书模式」浏览摘录：全屏摊开式阅读页，摘录一页一则（原文 + 页码 + 随想），ViewPager2 翻页动画，入口放在书籍详情页摘录区块右上角。
7. 书籍卡片与封面引入 3D 触感（悬浮回正效果）。

### 7.4 风险与原则

- 3D 效果不得牺牲可读性：正文页保持高对比、翻页动画时长控制在 400–700ms。
- 性能：翻书页只用属性动画 / 硬件加速变换；3D 书架放到 v2.0 并在中低端机降级为 2.5D。
- 原型为纯 CSS 3D（`docs/design/3D沉浸式阅读原型.html`、`docs/design/书籍展览馆原型.html`），仅验证交互与视觉方向，不代表最终技术实现。

### 7.5 北向愿景：每本书一座展览馆（2026-08-22 补充）

**概念**：书架是纪念馆的外墙，「走进一本书」= 走进它的私人展览馆。每本书拥有一个专属 3D 展厅，用户可自定义添加展品，展厅随展品增多向纵深生长。

**展品类型 ↔ 数据模型映射**：

| 展厅元素 | 数据来源 | 版本 |
|---|---|---|
| 摘录画框（墙上） | `notes` 表 `type=excerpt`（含页码、章节） | v1.1 |
| 随想画框（墙上） | `notes` 表 `type=note` | v1.1 |
| 纪念牌（评分 + 标签） | `books.rating` + `books.tags` | v1.1 |
| 封面原画 | `books.cover_path` / `cover_url` | v1.2 |
| 主题墙（尽头整幅） | `books.review` 读后感 | v1.1 |
| 中央展台旋转书 | `books` 本体 | v2.0 |
| 空展位（点击布展） | 「添加展品」入口 | v2.0 |
| 照片 / 心情 / 里程碑展品 | 未来扩展字段或新表 | v2.0+ |

**空间规则**：展品沿展厅两侧墙面纵深排布，纵深轴可按「页码顺序」或「记录时间」排列（用户可选）；添加展品自动寻找空展位，预设展位用满后展厅自动向深处延展。

**分阶段落地**：
1. v1.1：数据层就绪（notes 表即展品数据源），先做平面版「展品墙」（2D 画廊页面）。
2. v1.2：回忆展厅入口（那年今日聚合页复用展品组件）。
3. v2.0：SceneView 渲染真 3D 展厅（原型见 `docs/design/书籍展览馆原型.html`：滚轮前行、点击画框走近、空展位自定义布展）；中低端机降级为 2D 展品墙。
