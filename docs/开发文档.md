# 阅痕 ReadTrace 开发文档

## 1. 产品方向

阅痕 ReadTrace v1.0 是一个本地书籍记录工具。

界面气质采用“安静书架”：

- 简洁、耐看，不做复杂装饰
- 重点展示书籍、阅读状态、评分、标签和读后感
- 适合长期记录个人阅读经历
- 第一版优先保证可用、清晰、数据安全

v1.0 不做登录、云同步、AI、摘录和笔记。

---

## 2. v1.0 产品目标

v1.0 只做书籍记录核心功能：

- 添加书籍
- 查看书籍列表
- 查看书籍详情
- 编辑书籍
- 软删除 / 归档书籍
- 设置阅读状态
- 设置评分
- 添加标签
- 写简短评价
- 写读后感
- 使用 SQLite 保存数据

删除行为默认使用软删除，不物理删除用户数据。

## 4. 数据规则

### 4.1 软删除

所有删除默认都是软删除。

书籍归档时：

- `is_deleted` 改为 `1`
- `deleted_at` 写入当前完整 ISO 时间
- 不物理删除数据库记录
- 默认列表只查询 `is_deleted = 0` 的书籍

未来可以增加：

- 回收站
- 恢复书籍
- 彻底删除

彻底删除必须经过用户手动确认。

### 4.2 标签

数据库中 `tags` 使用 JSON 字符串保存。

数据库保存示例：

```json
["青春", "日本文学", "短篇"]
```

后端 API 返回给前端时转换成数组：

```json
{
  "tags": ["青春", "日本文学", "短篇"]
}
```

前端不直接处理 JSON 字符串。

### 4.3 评分

评分字段 `rating` 可以为空。

如果填写：

- 范围必须是 1-10
- 允许一位小数，例如 8.5
- 不允许小于 1
- 不允许大于 10

### 4.4 时间格式

完整时间字段使用 ISO 8601：

- `created_at`
- `updated_at`
- `deleted_at`

示例：

```txt
2026-06-03T23:02:00+08:00
```

阅读日期只保存日期：

- `start_date`
- `finish_date`

示例：

```txt
2026-06-03
```

## 5. 后端接口草案

v1.0 只规划书籍接口。

### 5.1 获取书籍列表

```http
GET /api/books
```

可选查询参数：

- `status`
- `keyword`
- `tag`

默认只返回未归档书籍。

### 5.2 获取单本书详情

```http
GET /api/books/{book_id}
```

### 5.3 添加书籍

```http
POST /api/books
```

请求体里的 `tags` 使用数组。

### 5.4 更新书籍

```http
PUT /api/books/{book_id}
```

### 5.5 归档书籍

```http
PATCH /api/books/{book_id}/archive
```

归档是软删除，不物理删除数据。

## 6. 前端组件规划

v1.0 组件：

- `BookList`：书籍列表容器
- `StatusFilter`：阅读状态筛选
- `TagList`：标签展示和筛选

v1.1 再增加：

- `NoteList`
- `NoteForm`

## 8. 第一轮约束

本轮只搭建项目结构和文档。

不做：

- 初始化 Vite
- 初始化 FastAPI
- 安装 npm 依赖
- 安装 Python 依赖
- 编写业务代码
- 生成数据库文件
