# 阅痕 ReadTrace 认证正式化接入指南

> 定位：把 v1.0.1 已就绪的「沙盒双轨」认证体系切换为线上正式通道。
> 沙盒模式保证无账号时本地开发/演示不被阻塞；配置下方任一组凭据后自动切换正式通道，无需改动代码。
> 文档基于 2026-09-01 的 v1.0.3 现状编写。

---

## 1. 双轨机制总览

| 能力 | 沙盒模式（默认，零配置） | 正式模式（配置后自动启用） |
|:---|:---|:---|
| 微信一键授权 | 本地确认卡 + 词库生成虚拟档案 | 拉起真实微信客户端授权（反射 OpenSDK） |
| 手机号验证码 | 本地生成并明文回显 | 阿里云短信真实下发 |
| 账号落库 | 同一套 `CuratorAccountManager`，无差异 | 同左 |

触发条件：
- 微信：`gradle.properties` 配置 `WECHAT_APP_ID` **且** `app/libs/` 放入微信 OpenSDK aar；
- 短信：`gradle.properties` 配置阿里云四项（AccessKey ID / Secret / 签名 / 模板 Code）。

## 2. 微信一键授权正式化

### 2.1 申请 AppID
1. 注册 [微信开放平台](https://open.weixin.qq.com)（需企业/组织主体，或认证过的个人主体）；
2. 「管理中心 → 移动应用 → 创建移动应用」，填写应用信息；
3. 审核通过后取得 **AppID**（形如 `wx1234567890abcdef`）与 **AppSecret**；
4. 在「开发管理 → 开发设置」填写 Android 应用的包名 `com.example.readtrace` 与**应用签名 MD5**（见下文 2.3）。

### 2.2 集成 OpenSDK（反射自动生效）
本项目按「零臃肿依赖」原则不直接声明 SDK 依赖，改为运行时反射。启用正式模式需要 SDK 类在运行时可见：

```bash
# 从 maven 中央仓库取 wechat-sdk-android 的 aar 产物（版本以官方最新为准），放入：
mkdir -p app/libs
# 将 wechat-sdk-android-*.aar 复制到 app/libs/
```

`app/build.gradle.kts` 已支持 `libs/*.aar` 自动打包（如无则补一行 `implementation(files("libs/wechat-sdk-android.aar"))`）。

### 2.3 配置与验证
```properties
# gradle.properties
WECHAT_APP_ID=wx1234567890abcdef
```
签名 MD5 获取（release 包）：
```bash
keytool -list -v -keystore readtrace-release.jks -alias <你的alias> | grep MD5
```
验证：安装后点击「微信一键授权」→ 应拉起真实微信授权页；授权回调后
`WeChatAuthManager.parseOfficialProfile(code)` 当前返回 null（纯本地无服务端），
应用自动降级为「已收到授权凭证 + 本地互联档案」，并在 Toast 中明确说明。

> 说明：完整获取微信昵称/头像需要服务端用 AppSecret 换 `access_token`。
> 本项目定位纯本地应用，**不接服务端**，故正式授权只做「凭证已收到」级别的降级闭环。
> 若未来要真实资料，需自建轻量后端做 code 交换，客户端不变。

## 3. 手机号验证码正式化（阿里云短信）

### 3.1 开通服务
1. 登录[阿里云控制台](https://dysmsapi.aliyuncs.com)，开通「短信服务」；
2. **签名管理**：申请签名（如「阅痕」），个人认证可申请「APP 应用名」类签名；
3. **模板管理**：申请验证码模板，内容需含 `${code}` 变量，例如：
   ```
   您的验证码为${code}，5分钟内有效。如非本人操作请忽略。
   ```
   审核通过后取得模板 Code（形如 `SMS_123456789`）。

### 3.2 获取 AccessKey
- 阿里云「AccessKey 管理」创建子账号（RAM），仅授予 `AliyunDysmsFullAccess` 或更小的发送权限；
- 得到 `AccessKey ID` 与 `AccessKey Secret`（Secret 仅创建时可见，务必保存）。

### 3.3 配置
```properties
# gradle.properties
ALIYUN_SMS_ACCESS_KEY_ID=LTAI5txxxxxxx
ALIYUN_SMS_ACCESS_KEY_SECRET=xxxxxxxxxxxxxxxx
ALIYUN_SMS_SIGN_NAME=阅痕
ALIYUN_SMS_TEMPLATE_CODE=SMS_123456789
```

### 3.4 验证
1. 配置后重新构建安装；
2. 进入「手机号先锋速登」，输入真实手机号获取验证码；
3. 手机应收到阿里云下发的验证码短信，页面不再显示沙盒明文；
4. 短信发送失败时自动降级沙盒并提示「短信通道暂不可用，已降级沙盒」。

### 3.5 安全说明
- AccessKey 经 `gradle.properties → BuildConfig` 编译进 APK，包内可被反编译提取；
- 强烈建议使用 RAM 子账号 + 最小权限（仅发送短信），并开启 AccessKey 轮换；
- 若对安全性要求更高，应改为自建服务端代理短信下发，客户端不持有任何密钥。

## 4. 常见问题

| 现象 | 原因 | 处理 |
|:---|:---|:---|
| 微信仍显示沙盒授权 | 未配置 AppID，或已配置但未放 SDK aar | 检查 gradle.properties 与 app/libs/ |
| 微信拉起后无反应 | 签名 MD5 与开放平台不一致 | 用 release 签名重算并更新开放平台 |
| 手机号仍是明文验证码 | 阿里云四项未配齐 | 检查四个配置项是否全部非空 |
| 短信提示「签名不匹配」 | 签名/模板未审核通过或填错 | 到阿里云控制台核对 SignName / TemplateCode |
| 短信发送失败 | 套餐余量不足 / 触发频控 | 控制台查看发送记录与错误码 |
