# 阅痕 ReadTrace 外部导入功能设计与开发计划

> 定位：解决新用户冷启动问题——手写导入一个作品要填十几个字段，门槛太高。
> 方案：提供「发现」页，展示热门作品，用户一键添加骨架数据（标题/作者/封面/简介/远程评分），之后在详情页慢慢补个人感想与纪念信息。
> 本文档基于 2026-08-31 的数据源调研与现有代码结构（DB v9 / 零网络依赖）编写。

---

## 1. 数据源选型结论

### 1.1 平台调研

| 平台 | 官方开放 API | 中文元数据 | 分类覆盖 | 结论 |
|:---|:---:|:---:|:---|:---|
| 豆瓣 | ❌（2017 年关闭） | ✅ | 书/影/音 | 只能爬虫，反爬严、合规灰色、随时失效，**放弃** |
| B站 | ❌（媒体元数据无官方 API） | ✅ | 番剧/影视 | 非官方 PGC 接口不稳定，**放弃** |
| **Bangumi (bgm.tv)** | ✅ 官方开放、免费 | ✅ | 书籍/动画/音乐/游戏/三次元 | **主数据源** |
| TMDB | ✅（免费 API key） | ✅ (zh-CN) | 电影/剧集 | 二期备选补充源 |

### 1.2 为什么是 Bangumi

- **官方开放 API**（`https://api.bgm.tv`，文档 https://bangumi.github.io/api/ ），无爬虫合规风险；
- 五大条目类型与阅痕媒介类型几乎一一对齐（见 §2.1）；
- 元数据质量高：中文名、封面、简介、评分、标签齐全；
- 用户群高度重合：阅痕面向 ACGN 爱好者，Bangumi 就是 ACGN 条目百科。

### 1.3 豆瓣的降级处理

豆瓣数据不爬取。若后续有需求，只做「用户手动粘贴豆瓣链接」级别的辅助功能，且不做自动抓取承诺。

## 2. 数据模型设计

### 2.1 分类映射

Bangumi `subject_type` → 阅痕 `MediaType`：

| Bangumi type | 含义 | 阅痕 MediaType |
|:---:|:---|:---|
| 1 | 书籍 | `BOOK` |
| 2 | 动画 | `ANIME` |
| 3 | 音乐 | `MUSIC` |
| 4 | 游戏 | `GAME` |
| 6 | 三次元（影视/纪实） | `MOVIE` |

> 注：Bangumi 无 type 5。电影/剧集归入「三次元」，一期先用它覆盖 MOVIE；若三期接 TMDB 则电影源切 TMDB，Bangumi 三次元保留为补充。

### 2.2 字段映射

| Bangumi 字段 | 阅痕字段 | 说明 |
|:---|:---|:---|
| `name_cn`（空则 `name`） | `title` | 优先中文名 |
| `infobox` 中「作者/导演/开发/艺术家/音乐人」等键 | `author` | 按媒介类型定义键名优先级，解析失败留空由用户补 |
| `images.large`（降级 `images.common`） | `cover_url` | **直接存 Bangumi CDN 在线地址，不做本地下载** |
| `summary` | `description`（**新增列**） | 现有 books 表无简介字段 |
| `rating.score` | `remote_rating`（**新增列**） | 与用户个人评分 `rating` 分离，互不覆盖 |
| `tags` | `tags`（可选拼接前 3 个） | Bangumi 标签与现有 JSON 格式对齐 |
| `date` | 可存入 `description` 头部或忽略 | 一期忽略 |

### 2.3 数据库迁移（DB v9 → v10）

`books` 表新增 4 列（`CREATE TABLE` 语句同步修改，`onUpgrade` 走 `ALTER TABLE`）：

```sql
ALTER TABLE books ADD COLUMN source_type TEXT;      -- 'bangumi' / 'manual'（NULL 视为 manual）
ALTER TABLE books ADD COLUMN source_id TEXT;        -- Bangumi subject id
ALTER TABLE books ADD COLUMN remote_rating REAL;    -- 远程评分 0~10
ALTER TABLE books ADD COLUMN description TEXT;      -- 简介正文
```

- `source_type + source_id` 建联合索引用于防重复导入；
- 老数据全部视为 `manual`，行为不变；
- 详情页排版需兼容新增的简介展示（远程评分 + 简介分区）。

## 3. 网络层设计

### 3.1 技术选型

**不引入任何第三方网络库**，沿用项目「零臃肿依赖」原则：

- HTTP：`HttpURLConnection`（Android 内置）；
- JSON 解析：`org.json`（Android 内置）；
- 并发：单例 `Executors.newSingleThreadExecutor()`（App 为 Kotlin 100% 但未引入协程，不为此功能新加依赖）；
- 主线程回调：`Handler(Looper.getMainLooper())`。

### 3.2 Bangumi API 对接要点

| 项目 | 说明 |
|:---|:---|
| 搜索 | `POST /v0/search/subjects`，body：`{"keyword": "...", "sort": "rank", "filter": {"type": [2]}}` |
| 热门榜单 | 同上接口，`keyword` 留空 + `sort: "rank"` + `filter.type` 按媒介过滤 |
| 条目详情 | `GET /v0/subjects/{id}`（含 infobox/summary/rating/images） |
| **User-Agent** | **必须自定义**，否则会被拒：`ReadTrace/<version> (Android; github.com/liuGuanYi-hub/ReadTrace)` |
| 限流 | 搜索按钮 500ms 防抖；榜单结果内存缓存 + 磁盘 JSON 缓存 24h，减少请求频率 |
| 超时 | 连接 8s / 读取 15s，失败静默降级为缓存或空态 |

### 3.3 封面加载（纯在线源）

- **不做封面本地下载**：导入落库的 `cover_url` 直接保存 Bangumi CDN 在线地址，与现有封面加载链路无缝衔接；
- 发现页与详情页均按需在线加载，配 `BitmapFactory` + 内存 LruCache 避免重复请求与列表卡顿；
- 无网/加载失败时显示占位封面，不阻断任何流程；用户也可随时手动更换本地封面。

## 4. 产品与页面设计

### 4.1 入口与页面结构

```
AddBookActivity（添加页）
  └─ 顶部新增「🔍 从发现页导入」入口
        └─ DiscoverActivity（发现页，新建）
             ├─ 顶部：媒介分类 Tab（书/番/影/音/游，复用 MediaType 五色 chips）
             ├─ 搜索框（关键词搜索，走 §3.2 搜索接口）
             └─ 封面网格（2~3 列，标题 + 远程评分角标，下拉刷新）
                   └─ 点击封面
                        └─ 条目预览（BottomSheetDialogFragment）
                             ├─ 封面 + 中文名/原名 + 简介（3 行可展开）
                             ├─ 远程评分 + Bangumi 标签
                             └─ [添加至纪念] 按钮
                                  └─ 状态选择弹层（想读 / 在读 / 读过 / 想看 等，沿用现有 status 取值）
                                       └─ 落库（填充骨架字段）→ 跳转详情页或返回列表
```

### 4.2 交互原则

1. **一键添加必选状态**：点「添加至纪念」弹出状态选择，一步到位不留歧义；
2. **骨架 vs 灵魂分离**：远程数据只填客观字段，个人评分、感想、摘录、纪念字段全部留空，引导用户在详情页补全（详情页对「仅骨架未补全」的条目显示轻提示，如「还没有留下你的想法」）;
3. **防重复**：按 `source_type + source_id` 精确查重，命中则按钮变「已在藏库」并禁止重复添加；按 `title + media_type` 模糊查重时弹「可能已存在」提示供用户选择；
4. **无网降级**：无网络时入口保留但发现页显示空态 + 重试，不影响原有手写添加流程。

### 4.3 与纪念功能的衔接

导入完成后详情页按现有纪念功能逻辑运转：摘录、笔记、心智五维、护照盖印等照常可用。一句话定位——**导入的是骨架，纪念才是灵魂**。

---

## 5. 合规与隐私

- 直连 Bangumi 官方 API，不采集、不上传任何用户数据到第三方（保持「纯本地数据掌控」定位）；
- 遵守 Bangumi API 礼貌约定：自定义 UA、结果缓存降低请求频率；
- 简介与评分为 Bangumi 用户贡献内容，详情页简介区底部注明来源（小字「简介来自 Bangumi」）。

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|:---|:---:|:---|
| Bangumi API 变更/限流 | 中 | 网络层单一出口类封装（`BangumiApiClient`），变更只改一处；缓存兜底 |
| 电影分类数据偏弱 | 中 | 一期接受；v1.0.2 评估接 TMDB |
| 封面 CDN 国内可达性 / 弱网无封面 | 中 | 纯在线源按用户决策保留；若实测可达性差，可复用 `cover_cdn_map.json` 的 CDN 映射经验做镜像兜底，或用户手动换本地封面 |
| 简介文本过长撑爆详情页 | 低 | 详情页做折叠展开（3 行 + 展开） |
| 新增列对导出/SAF 兼容影响 | 低 | 新列均可空，导出 JSON 增量字段，旧版本导入端忽略未知字段 |
