# 02 · 功能映射表（Android → 小程序可行性分档）

> 依据 Android 端 183 个 Kotlin 文件与 Activity 清单盘点。
> 分档：**A = 直接可做**（wx API 齐全，纯移植）｜**B = 需改造**（要云函数/降级/换实现）｜**C = 建议放弃**（App 端独占）。

## A 档 · 直接可做（小程序版核心，一期完成）

| Android 功能 | 对应实现 | 小程序端做法 |
|---|---|---|
| 主页记录台（五媒介统计网格、那年今日） | MainActivity | 云数据库聚合查询 + 首页统计卡；那年今日按 `createdAt` 月日匹配 |
| 库藏列表（五媒介筛选 + 搜索） | MediaHubActivity | **P19 已有雏形**（`pages/library`），补云数据库分页 |
| 添加/编辑条目（评分、标签、状态、短评、长评） | AddBookActivity / AddNoteActivity | 表单页 + 评分组件；字段与 Schema v4 同构，TS 类型已建好（`utils/models.ts`） |
| 极速速记（一句话分词 + 五态秒存） | NaturalQuickAddParser | **P19 已有雏形**（`pages/quick-log`），分词逻辑纯 TS 可整体移植 |
| 心印六维雷达 | MindprintConstellationActivity | Canvas 2D 画雷达图（`deriveMindprint` 推导函数已同构） |
| 我的最爱 / 策展 | CuratorFavoritesActivity | 云数据库 `rankOrder` 排序查询，列表 + 封面条 |
| 回收站 | TrashActivity | 软删标记 + 恢复/彻底删除，查询过滤即可 |
| JSON 备份导出/导入 | BackupActivity / WechatMinappSyncProtocol | `FileSystemManager` 写文件 + 转发给好友存档；`wx.chooseMessageFile` 导入 → **一期与 Android 互通的桥** |
| 微信登录 | WeChatAuthManager | `wx.login` 原生，几行代码 |
| 分享 | — | 小程序卡片分享是天然优势（App 端反而更麻烦） |

## B 档 · 需改造（二期）

| Android 功能 | 障碍 | 改造方案 |
|---|---|---|
| Bangumi 搜索 + 一键导入 | 域名白名单 | **云函数代理** `api.bgm.tv`（云函数可请求任意 HTTPS）；搜索结果缓存进云数据库 |
| Google Books 封面补全 | 域名白名单 | 同上，云函数代理；封面图转存云存储 |
| AI 功能（AI_BASE_URL，DeepSeek key） | 域名白名单 + **key 不能放小程序端** | 云函数持有 key 调用；顺手解决了 App 端 key 打包进 APK 的安全隐患 |
| WebDAV 同步 | PUT/MKCOL 兼容性未知 + 域名备案 | 先用"JSON 导入导出"过渡；二期做云函数转发 WebDAV，或直接以云数据库为云端 |
| 3D 银河星云（gallery3d） | 无 OpenGL ES | 方案 1：WebGL + Three.js（工作量≈重写）；方案 2：**Canvas 2.5D 星图降级**（推荐，保留"银河"意象） |
| 时间线浏览（Anime/MediaTimelineScroll） | 自绘滚动容器 | Scroll-View 纵向时间轴，纯排版工作 |
| 海报工坊（QuotePoster / MovieTicketPoster / GameCartridgePoster / ResonancePoster / ExLibrisStudio） | Android 自绘 View | **Canvas 2D + 离屏导出**，小程序做海报反而比 Android 简单；保存相册需 `scope.writePhotosAlbum` 授权 |
| 年刊（AnnualChronicleStudio） | 依赖海报能力 | 建立在海报工坊之上，三期 |
| 徽章（BadgesActivity） | 本地统计 | 纯逻辑，随时可做，二期顺手 |
| 封面加载（cover_cdn_map.json CDN 映射） | CDN 域名需备案 | 该 CDN 若已备案可直接配进白名单；否则转存云存储 |
| 手机号登录 | 短信成本 | 改微信 `getPhoneNumber` 快捷授权（免费） |

## C 档 · 建议放弃（App 端独占）

| 功能 | 放弃原因 |
|---|---|
| 网易云 Cookie VIP 播放 | 音频流域名 + Cookie 安全 + 审核风险三重不可行；小程序端保留纯视觉黑胶 |
| UGC 社区（community 模块） | 个人主体无社交类目资质 + 内容审核义务；留在 App 端 |
| 桌面 Widget | 平台无对应物 |
| 生物识别锁 | 系统级能力缺失，Soter 兼容性差 |
| 豆瓣数据爬取 | 反爬 + 域名 + 灰色地带；正式版不上，仅供开发调试 |
| 文件迁移（DataMigrationActivity） | 一次性历史功能，小程序端从 Schema v4 起步不需要 |

## 覆盖率小结

- A 档（一期可上线）：**10 项**，覆盖日常记录主流程 ≈ App 端 60% 使用频次
- B 档（二~三期）：**12 项**，其中 Bangumi 导入与海报工坊是差异化亮点
- C 档：6 项明确出界，App 端独占
- **产品定位**：小程序版 = 「随手记 + 随时看 + 秒分享」的轻量入口；App 版 = 重交互创作台
