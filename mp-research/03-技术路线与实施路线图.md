# 03 · 技术路线与实施路线图

## 1. 技术选型对比

| 路线 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| 原生小程序（WXML/WXSS/TS） | 性能最好、无编译层 | 从零重写，丢掉 P19 已有成果；锁死微信一端 | 不采用 |
| **uni-app Vue3 + TS** | **P19 雏形已就位**；数据模型同构已建立；同一代码未来可出 H5/App；社区成熟 | 编译层偶有坑；包体积略大 | ✅ **采用（继续）** |
| Taro React | React 技术栈、京东系维护 | 同样要迁移 P19（Vue 代码）；团队无 React 小程序积累 | 备选不动 |

> 决策依据：`mp-readtrace/` 已完成两个核心页面 + 数据模型镜像 + WebDAV 同步工具 + 两个特色组件（DioramaCard / VinylPlayer），沉没成本即增量价值，且 uni-app 与 Android 端 Kotlin 模型的 TS 镜像已经写完。

## 2. 架构方案对比

### 方案甲 · 零后端极简（Local-First）
```
小程序(uni-app) ── wx.storage(≤10MB) ── JSON 导入导出 ── Android(WebDAV/文件)
```
- 优点：0 月费、无需备案域名、审核简单（纯工具类）
- 缺点：多端同步靠手动导文件；Bangumi/AI 等外部能力全没有；10MB 存储上限
- 适合：只想先"试水"小程序形态

### 方案乙 · 微信云开发（推荐）
```
小程序(uni-app) ── 云数据库(Schema v4 同构 JSON 文档) ──(二期)── Android
       │                │
       └── 云函数：① Bangumi 代理  ② AI Key 托管  ③ WebDAV 转发(可选)
                        │
                   云存储：封面图 / 海报成品
```
- 优点：免运维；云函数解决全部域名白名单问题；微信登录/手机号天然打通；二期可让 Android 也写同一云数据库，真正"多端漫游"（`WechatMinappSyncProtocol` 就是为此预留的）
- 缺点：长期 19.9 元/月；云函数出网流量计费（封面走云存储规避）
- 费用：开发期 0 元（免费体验环境），上线后 19.9 元/月

### 结论：**乙为主，甲为裙底**
一期的"JSON 导入导出"（方案甲的桥）无论如何都要做——它是用户从 App 迁移数据进小程序的通道，之后所有数据逐步落到云数据库。

## 4. 风险清单与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 云开发免费环境上线后 15 天到期 | 高（忘续费=数据环境停） | 上线前设置日历提醒；到期前转 19.9/月套餐；数据定期 JSON 导出备份 |
| 云函数出网流量超配额 | 中 | 封面图不代理，直连备案 CDN 或转存云存储 |
| 类目审核驳回（功能越界） | 中 | 申报「工具-效率」，页面内不出现"社区/动态/留言"字样 |
| `wx.request` 直连 WebDAV 的 PUT/MKCOL 兼容性 | 中 | 一期不依赖；二期一律云函数转发 |
| 个人主体不能 web-view | 低 | 当前方案不依赖 web-view |
| 10MB storage 上限 | 低 | 本地只缓存索引，详情按需拉取 |
| 网易云 Cookie 若用于云函数=密钥入库风险 | — | 已决定放弃播放，**Cookie 永不进小程序侧任何代码/云函数**（遵守敏感信息规则） |

## 5. 与 Android 端的协同改造点（M1/M5 时）

1. `WechatMinappSyncProtocol.exportToMinappPayload` 增加"导出为文件并分享"入口（分享给文件传输助手 → 小程序 `wx.chooseMessageFile` 接收），这是最顺滑的迁移链路
2. Android 端评分/状态枚举的 `databaseValue` 与 `utils/models.ts` 保持单测级一致（两端字段命名已同构，加对比测试即可）
3. 封面图 CDN 域名确认备案状态，决定小程序端走白名单直连还是云存储镜像
