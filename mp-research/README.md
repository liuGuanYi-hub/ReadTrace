> 建立时间：2026-09-07 13:10 ｜ 状态：调研结论稿
> 结论先行：**可以做，且项目里已有可复用的地基（`mp-readtrace/` uni-app 雏形 + Android 端 `WechatMinappSyncProtocol.kt` 数据契约）。推荐走「uni-app + 微信云开发」路线，以"工具类目"个人主体发布。**

## 一句话结论

阅痕的核心资产是「本地 SQLite + WebDAV 同步 + 五媒介数据模型」，这三样在小程序端都有对应解法；
真正的硬约束只有四条：**域名白名单、个人主体类目限制、云开发收费、网易云播放不可行**。

## 关键结论速览

1. **技术栈：继续用已有的 uni-app（Vue3 + TS）**，不推倒重来。`mp-readtrace/` 已有库藏列表 + 极速速记两个页面，数据模型与 Android JSON Schema v4 100% 同构。
2. **外部 API（Bangumi / AI）必须走云函数中转**：`wx.request` 只能请求「管理后台配置过的 HTTPS + ICP 备案域名」，`api.bgm.tv` 不在自己名下无法配置；云函数不受此限制，是标准解法。
3. **数据层推荐微信云开发**：云数据库直接存与 Schema v4 同构的 JSON 文档，免运维；新用户有免费体验环境（活动截止 2026-12-31），上线后基础套餐 **19.9 元/月**。
4. **同步策略分两步**：一期用「导入/导出 JSON 文件」与 Android 端互通（复用 `WechatMinappSyncProtocol` 的 payload 格式）；二期再打通云数据库为双端共同云端。
5. **明确放弃**：网易云 Cookie VIP 播放（域名+Cookie 安全+审核三重风险）、桌面 Widget、生物识别锁、UGC 社区（个人主体无社交类目资质）。
6. **意外优势**：微信登录在小程序端是 `wx.login` 原生能力，比 App 端微信 OpenSDK 接入简单得多；海报工坊用 canvas 导出也比 Android 自绘 View 省事。
